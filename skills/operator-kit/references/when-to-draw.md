# When to draw a page, and when to answer in chat

**The rule:** if the answer has a shape, draw it. If it only has a length, say it.

| Situation | Where | Why |
|---|---|---|
| Position, size, layout, colour | Page | Words cannot settle a spatial question. Three readings as pictures, then one click. |
| Proof something shipped | Both | The comparison needs a page; the verdict and link go in chat. |
| More than two things waiting on a person | Page | Needs buttons, and has to survive the session. One waiting item is a chat line. |
| A number with a trend or a breakdown (roughly four or more figures) | Page | It is a chart. Every figure carries its definition and source. |
| One or two numbers | Chat | A sentence is faster. Drawing it is decoration. |
| Status of one thing | Chat | Short, and usually read on a phone between other things. |
| Anything urgent — a stall, a failed release, a wrong number spotted | Chat | Speed wins. A page is one click too many when something is on fire. |
| Something several people act on, or come back to | Page | It holds answers and gets reopened tomorrow. |
| A release note | Chat | Four lines. It goes where people already are. |

## Two hard lines
- Never a page to say something short.
- Never a paragraph to describe something visual.

Unsure? Draw the picture **and** put three lines plus the link in chat. The reader picks.

## Cost
A page costs real output the first time it is written and almost nothing after that, because updates write a few lines of data into a page that already exists. A surface someone returns to pays for itself; a page for a single number never does.

## In-chat drawing
Small shapes belong in chat as plain text: a bar of blocks for counts (`██████ 6`), an arrow for a change (`3 → 7`), an indented list for a hierarchy. Reach for this before building a page for something small. Nobody on this team says "visualise it" or "chart it out", so never wait to be asked.
