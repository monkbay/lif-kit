Prove the state of: $ARGUMENTS

Load the `operator-kit` skill and follow the Proof contract in `references/templates.md`.

1. **Find the thing** — by ticket id, by feature name, or by description. Several matches: list them and ask which one. Never guess between two.
2. **Look at it for real.** Open the screen in the browser, sign in, walk the path a user would take, and screenshot every step. Read the console and the network tab for errors while you are there.
3. **Compare** what is live against the approved picture, point by point, using the numbered changes from the preview. State matches and differences separately — a difference is not a failure until someone says so.
4. **Re-check each acceptance line yourself.** If one fails, fix it if it is yours to fix and say you did, or file it back with what you saw. Never hand a failing check to the operator as a question.
5. **No evidence means blocked, not done.** If you could not open the screen, could not sign in, or the flag is off, the verdict is `chưa chứng minh được / not proven`, with the one thing needed to prove it. Never write "deployed" or "done" on an unevidenced check — this is the single most important rule in the kit.
6. **Always end with where it lives**: the screen in the words staff use, the link, which hotels have it switched on and which do not, and a check anyone can do in 30 seconds.
7. **Surface**: the comparison goes on a page; three lines and the link go in chat.
